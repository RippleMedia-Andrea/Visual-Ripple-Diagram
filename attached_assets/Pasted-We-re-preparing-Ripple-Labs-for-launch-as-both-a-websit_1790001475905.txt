2. Save progress to the database

Replace the localStorage-only saving in ripple-journey.tsx with database saving. Remove the unused template tables conversations and messages in lib/db/src/schema and add:

journeys: id, user_id (FK, cascade delete), status ("in_progress" | "complete"), current_stage_idx, selected_prompts (jsonb), purpose_options (jsonb), purpose_statement (text, nullable), created_at, updated_at, completed_at
journey_messages: id, journey_id (FK, cascade delete), stage (reveal | identify | pinpoint | personalize | live | expand), role (user | assistant), content, created_at

API routes (all require a signed-in user, and a user can only access their own journeys):

GET /api/journeys/current: the user's in-progress journey with messages grouped by stage (create one if none exists)
PATCH /api/journeys/:id: update current_stage_idx, selected_prompts, purpose_options, purpose_statement, status
POST /api/journeys/:id/restart: mark current journey complete/archived and start a fresh one ("Begin a New Journey")

The front end loads the journey from the API on page load and saves changes through these routes. Keep localStorage only as a temporary offline cache if helpful, never as the source of truth.

3. Protect the AI endpoint

Update POST /api/ripple/chat:

Require a signed-in user; return 401 otherwise.
Accept a journeyId and verify it belongs to the user.
Save the user's message and the full assistant reply to journey_messages on the server (after the stream finishes), so conversations are saved even if the browser closes.
Rate limit per user: 40 AI messages per hour and 200 per day. When the limit is hit, return a friendly message: "You've done a lot of meaningful reflection today. Take a breath and come back a little later to continue."
Reject messages over 4,000 characters and invalid stages.
Lower max_tokens from 8192 to 1500.
Restrict CORS to our own web domains (and allow the future mobile app, which doesn't send an Origin header).
